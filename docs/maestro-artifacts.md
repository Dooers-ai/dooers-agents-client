# Maestro artifacts

`client.artifacts` and `useMaestroUploads()` are separate from legacy `useUpload`, settings uploads and `AgentProvider`. A connected, authenticated Maestro client must negotiate `attachments.durable`; a capability is not permission. Human pre-thread uploads use the configured organization/principal/workspace and never an incidental selected agent.

`add(blob, filename, { authorize })` retains the Blob, original filename, generated idempotency key and SHA-256 in private scoped memory. The optional explicit-action authorization callback runs before each attempt and receives an AbortSignal. It can obtain an artifact-write credential; the SDK never mints one. Pending/error drafts block `content()`. `retry(id)` reuses the same File/key/hash and emits no new message. `remove(id)` aborts and ignores late replies. `clearUploads()` releases draft intentions without deleting linked server objects. Client reset/dispose/access loss clears all Files, streams and Blob resources. Draft Files are not stored in localStorage, IndexedDB or a canonical event; browser reload requires selecting the File again.

The multipart profile posts metadata before bytes to the configured Maestro API `/artifacts`; it does not invent a `/complete` request. It accepts only the ready multipart response matching filename/type/actual size/hash. The server remains authoritative for MIME inspection, quotas, limits and expiry. The local default bound is 8 MiB/file, configurable to 64 MiB, with at most 16 draft intentions. Expired ready references are rejected by `content()`; selecting the File again is an explicit new upload.

`content()` returns public attachment parts with `artifact_id` and validated presentation metadata only. Publication and retry still belong to `client.send`/`client.retry`; an uploaded file is not a canonical message. The UI lists canonical references from authorized replay rather than inventing a new artifact listing endpoint.

`open(threadId, attachment, signal)` requires the reference in the client's authorized canonical history for that thread, then performs a new bearer-authenticated proxy read. It never follows a URL from message data, exposes a bearer URL or resolves against an agent. Redirects/cookies/cache are disabled. It validates server headers and exact bounded length; partial or canceled bytes never become a Blob URL. At most 2 reads and 8 live resources are retained. Each resource exposes a local `blob:` URL and `release()`, and expires within 60 seconds. Reopening is an explicit new authorized read, with no polling or automatic renewal. Revocation/reset/closeThread releases resources and aborts pending reads. Bytes already downloaded by the user cannot be recalled.

Do not render active HTML/SVG/PDF in same-origin frames. Web previews allow only configured raster images and audio; other files are download-only. The legacy agent URL helpers and exports are unchanged.

Review correction E08-08 v2: `open()` aborts its native transport in `finally` before releasing the read slot, including early rejection of missing/invalid safety headers. A response that never closes cannot remain active outside the two-read bound until its deadline. The `nosniff` guard remains required; the Maestro proxy must explicitly expose `X-Content-Type-Options` over CORS.
